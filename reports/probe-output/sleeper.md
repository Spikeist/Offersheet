## Decisions

- Sleeper sanitizer: user IDs, display names and team names are numbered by roster (owner of roster N → user 2000…0N / Owner N / Team N; co-owners and other users after the last roster), league IDs/names by league (League 1 = the probed league); every placeholder comes from one allocator, and the run fails the fixture check if two raw values ever share one. Names are replaced however short (short ones on exact match only). Free text (player nicknames, notes, league descriptions, chat previews) becomes [text N]; notification flags, W/L record strings, mascot item types and values equal to ordinary data (positions, statuses, a player's own name) are left as they are. IDs seen only while choosing the league go to a separate, ID-only redaction map, and every stranger's identity seen while choosing goes to a git-ignored watch list that npm run check:leaks loads.
- Fallback Sleeper league: SLEEPER_USERNAME and SLEEPER_LEAGUE_ID are blank, so the probe picks a stranger's public in-season league by a salted random walk over public league member lists (seeded from example IDs in Sleeper's API docs), preferring one that exercises trades, IR and K/DEF slots. The random salt and the walk's details live only in the git-ignored choice file, so the pick can't be re-derived from the code, and the committed reports and fixtures describe the league only generically. The seed's league list isn't committed (a one-entry example stands in). The probe switches to Parker's league automatically once either variable is set.
- currentWeek = /state/nfl `week` (the NFL week whose games are next); completed weeks = start_week..settings.last_scored_leg. On this run (a Tuesday, US Eastern) display_week (3) and settings.leg (3) lagged behind week 4; settings.leg advances only when the league's weekly waivers run (probe:sleeper-codes CODES.leg warn), so neither is used for the current week.
- Sleeper tradeReview = 'league_vote' when settings.veto_auto_poll = 1, else 'none'; 'commissioner' is never produced (Sleeper shows no approval step in the data). trade_review_days matters only with the poll (probe:sleeper-codes CODES.tradeReview warn).
- Sleeper projections → league points: apply the key map (DEF st_td → def_st_td; player def_kr_td and pr_td → st_td; player def_kr_yd → kr_yd; drop DEF rows' def_kr_td/def_pr_td/pr_td/pr_yd), then Σ scoring_settings[k] × stat; /stats needs no map.
- Sleeper team name = users[].metadata.team_name when set, else the owner's display_name (what the Sleeper app shows).
- Sleeper injury_status → normalized: Questionable→QUESTIONABLE, Doubtful→DOUBTFUL, Out→OUT, IR→IR, PUP→PUP, Sus→SUSPENDED, NA→NA; null/"" → ACTIVE. Proposed for statuses outside the enum: DNR (did not report) → OUT, COV (COVID list) → OUT. Seen in the players DB today: null 11331, Questionable 280, IR 244, Out 224, NA 96, PUP 38, Sus 11, DNR 2, COV 2, "" 1.
- Regular season = weeks start_week..playoff_week_start−1 from settings; matchups for weeks ≥ playoff_week_start are ignored until the playoffs start, and winners_bracket is read for structure only (its seeds are provisional mid-season).
- Transaction weeks: use `leg` for the fantasy week, but activity windows (acceptance model 'a', §11) use the `created` timestamp, because offseason moves can be filed under leg 1.
- Sleeper free agents = players DB (active, NFL team set, a position the league can start) minus every rostered player (players[] incl. IR/taxi). The top 50 per position by league-scored projection (real projection rows only, not ADP stubs) become LeagueSnapshot.freeAgents. Waiver status isn't exposed; waiver_clear_days is in settings.
- Sleeper projections' last_modified is a per-week batch stamp: every stamped row of a week carries the same day (week 3: 2026-09-29 on 447 rows (447 real); week 4: 2026-09-29 on 462 rows (462 real); week 5: 2026-09-28 on 468 rows (468 real); week 17: 2026-09-28 on 509 rows (509 real)), so it can't show whether far-future numbers were re-projected (probe:shared PROJ-S.lastModified, warn: last_modified sits on exactly the projected rows, one UTC day per week:). The far-future stamps are after the season start (2026-09-09), not the preseason §2.3 describes; §6's shape-only use of future weeks stands.
- FantasyCalc format for Sleeper: isDynasty from settings.type (2 → dynasty values; 1 keeper → both redraft and dynasty; else redraft), numQbs = 2 when a SUPER_FLEX slot or 2+ QB slots exist, numTeams = nearest of 8/10/12/14, ppr = nearest of 0/0.5/1 to scoring_settings.rec; no tep parameter is sent here (bonus_rec_te is reported; TE-premium values are the shared probe's to verify).
