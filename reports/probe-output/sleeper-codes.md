## Decisions

- No new crawl (CLAUDE.md §0.6: strangers' leagues are crawled only with --allow-crawl, after asking Parker): every league, user and draft request was served from the HTTP cache or skipped, and the analysis uses the last crawl's data.
- Sleeper trade-deadline rule for Phase 1 (proposed): trades are open while the league's settings.leg ≤ trade_deadline, not the /state/nfl week — no trade completed after leg D in 6 leagues that traded at the deadline; 10/39 completed trades finished in the NFL week after their leg (a league's leg advances only at its weekly waiver run); 3 of 7 leg-D trades completed during week D's Sunday/Monday games (no lock at kickoff); on this probe's Tuesday run /state/nfl already said week 4 while last_scored_leg was 3 in every in-season league, so the /state/nfl week can run a week ahead of the league's leg.
- Sleeper tradeReview mapping (proposed): 'league_vote' when settings.veto_auto_poll = 1 (3/3 such trades had a veto poll), otherwise 'none' (with the poll off, 16/24 trades in leagues with trade_review_days ≥ 1 completed within 24 h); veto keys missing (75 2026 leagues) → 'none' with an Import Report warning until verified; 'commissioner' is never produced (no approval step in the data).
- Sleeper currentWeek comes from /state/nfl (week); settings.leg lags until the league's weekly waiver run, and settings.last_scored_leg is the last completed week.
- Sleeper omits settings keys freely; Phase 1 defaults for missing keys (from this sample): league_average_match missing in 6 → unverified (assume 0); best_ball missing in 72 → 0 (verified); veto_auto_poll/veto_votes_needed missing in 75 → 'none' (unverified).
- Evidence rule for this item: a code value is ✅ only with ≥ 3 independent leagues (distinct 2026 leagues; earlier seasons of the same league don't count) and none contradicting, or ≥ 10 with ≤ 10% contradicting; below that it is ⚠️.
- Sampling: snowball through league member lists, at most 5 new leagues per user so a few very active accounts can't dominate; previous seasons chosen greedily so every value of each code is covered where available. Every ordering uses a random salt kept only in data-local/ (git-ignored), so the committed code can't reproduce which public leagues were sampled.
- Crawled leaguemates' IDs (league, user, draft) are registered with the Redactor so no console line or report can show them; display names and league names are never stored in the trimmed records, only keyword flags; every identity in the raw captures goes to a git-ignored watch list that check:leaks loads; and the report is checked against every name seen before anything is printed.
