## Decisions

- FantasyCalc: send tep only for TE-premium leagues (te+ or te++), percent-encoded (URLSearchParams does this); omit it otherwise ("Default none" per the docs, FC.tep).
- FantasyCalc: always send the nearest supported numTeams (8/10/12/14) ourselves, and don't fetch unsupported sizes: in the Phase 0 run of 2026-09-29, numTeams=16 returned HTTP 200 with values identical to the 12-team default (198/198 players; only maybeTier differed), i.e. a silent fallback. The format was then dropped from the daily set, since fetching it fetched the 12-team values a second time.
- FantasyCalc picks: "FP_…" keys in sleeperId/mflId/fleaflickerId belong to PICK rows and are never matched as player IDs; league picks map by name ("YYYY Nth", plus "(Early|Mid|Late)" for 2027), not by key, because generic and tiered keys number rounds differently (FC.picks).
- FantasyCalc fixtures are trimmed (top 50 per format + picks + TEs where relevant), because the terms forbid reproducing substantial portions of their data.
- DynastyProcess duplicates: when an ID maps to several rows, prefer the row whose sleeper_id is an active Sleeper player, and log the ambiguity as an import warning (applied in the ESPN → Sleeper map below).
- ESPN → nflverse team codes are derived by joining games on ESPN's event id, never hand-mapped (differences found: LAR→LA, WSH→WAS).
- Bye weeks come from the NFL schedule (nflverse / ESPN byeWeek), never from projections: an empty ESPN entry means 'not projected' (PROJ-E.empty), and ESPN projects D/ST units in their own bye week.
- ESPN projections: one leaguedefaults/3 kona_player_info call per 6 h carries every weekly projection; trim each player's stats[] to the current season before caching (the full 500-player pool is ~15 MB).
- ESPN D/ST → Sleeper DEF ids are joined on the team nickname (ESPN proTeams name vs Sleeper DEF last_name), not on abbreviations, which differ (WSH→WAS).
- ESPN kona_player_info returns only 50 players without an X-Fantasy-Filter, so every pool request sends the espn-api pool filter with an explicit limit.
