- MFL lineups are a starter total plus a min–max range per position, not slots. This league (QB 1-2, RB 0-4, WR 0-5, TE 1-3, PK 1, DT+DE 1-3, LB 1-3, CB+S 1-3; 14 starters, 5 of them IDP) can't be expressed exactly as SlotDef[] — offense: 4 position range(s) cap the 6 flex spots (QB ≤ 1 extra, RB ≤ 4 extra, WR ≤ 5 extra, TE ≤ 2 extra) and their caps add up to 12 > 6, which no SlotDef set can express; SlotDefs alone over-allow them, so the solver needs starterCaps (evidence B.flex). Options: (a) add optional per-position starter caps (min/max) to LeagueSettings and solve lineups with a flow network that honours them; (b) approximate with SlotDefs and warn on the Import Report.
- MFL roster limits carry minimums as well as maximums (QB ≥ 1, RB ≥ 1, WR ≥ 1, TE ≥ 1, K ≥ 1, DL ≥ 1, LB ≥ 1, DB ≥ 1) but CLAUDE.md §4 positionLimits holds maximums only — evidence B.positionLimits (GET https://{leagueHost}/2026/export?TYPE=league&L={leagueId}&JSON=1 → HTTP 200, league.rosterLimits.position[].limit) — options: (a) add optional positionMinimums and make auto-drops respect them; (b) ignore minimums (a trade could leave a roster illegal on MFL) and warn on the trade card.

- CLAUDE.md §2.6 says "Follow redirects to the league's wwwNN host", but (1) api_info warns a wrong-host redirect "may be delayed, or if the system is under too much stress, it may be denied", (2) this run's api-host league request was answered directly (HTTP 200, no redirect), and (3) Node's fetch drops the Cookie header on a cross-host redirect, so a private league would silently answer as a guest — evidence X.redirect, DOCS.hosts — options: (a) send league requests to league.baseURL's host (implemented); (b) follow redirects by hand, re-attaching the cookie only for https *.myfantasyleague.com (implemented in lib/mfl/client.ts; offline-tested, untested live: no MFL login).

- CLAUDE.md §0.9 says to back off exponentially on 429/5xx, but api_info says "If a request fails, don't retry" and "Wait one second between making requests" (DOCS.rate) — the probe follows MFL for MFL hosts (no retries; a 429 stops MFL calls for the run) — options: (a) keep MFL's rule as a documented exception to §0.9 (recommended); (b) allow one delayed retry on 5xx only.

## Decisions

- FantasyCalc format for this league: isDynasty=true (assumed from the A.leagueType signals: dynasty), numQbs=2 (QB range allows 2 starters), numTeams=10, ppr=0.5; the TE premium (TE 1 per catch) is not passed — the tep parameter is still unverified (shared probe).
- League requests go to the league's own host (league.baseURL for MFL_LEAGUE_ID, the search hit's homeURL for the test league); non-league TYPEs to api.myfantasyleague.com — as api_info asks. Redirects are followed by hand (redirect: "manual") and only to https *.myfantasyleague.com, so a login cookie survives an api → wwwNN hop.
- Pacing: every *.myfantasyleague.com request (api host, league hosts, docs pages, redirect hops) shares one bucket in lib/http.ts, ≥ 1.2 s apart; retries: 0 on every MFL request; one 429 stops further MFL calls for the run (api_info: "If a request fails, don't retry").
- Cache: league data 10 min, league-scored projections 6 h, players DB 24 h (api_info: "no more than once per day"), allRules 7 days, docs pages 7 days (HTML cached on purpose), NFL schedule/byes 7 days, injuries 6 h, the leagueSearch result 24 h plus the saved test-league choice; MFL HTTP-200 error bodies are never cached.
- Private leagues: log in with MFL_USERNAME/MFL_PASSWORD via POST and send the MFL_USER_ID cookie; the APIKEY alternative is not used because it travels in the URL query string.
- Test league (MFL_LEAGUE_ID blank): one public TYPE=leagueSearch, then a few candidates in a random order keyed by a salt that lives only in the git-ignored choice file, until a public, in-season 10–12 team league with IR and taxi slots in use (this one: dynasty); the IDs and names of the leagues looked at go to the git-ignored watch list for check:leaks.
- MFL responses are put in canonical order (sorted keys; id-keyed arrays sorted — lib/mfl/canonical.ts) before identities are registered and fixtures saved, so placeholders and committed fixtures stay stable run to run; fixtures/raw keeps MFL's exact bytes.
- Scoring semantics taken from MFL's Scoring Rules Setup help: *N per unit, a/b stepped every-b, plain N flat award in range, thresholdPoints = formula scoring; rules in overlapping position groups add up. lib/mfl/rules.ts compiles them to Sleeper-key rates + stat ≥ threshold bonuses and reports what doesn't fit.
