## Where live data differs from CLAUDE.md

The evidence for each item is in the named probe output.

**ESPN (§2.2)**
1. `pointsOverrides` is keyed by the player's `defaultPositionId`, not the lineupSlotId, and the override replaces the base points rather than adding to them. Evidence: TE players match 5/5 under the position reading and 0/5 under the slot reading. Replace matches 72/72 and add 0/72. ESPN's own `statIdToOverridePosition` keys head-coach stats with 14, the HC position id. (espn: K.overrideKeys)
2. A wrong season returns HTTP 404 JSON `GENERAL_NOT_FOUND`, not HTML, 401 or 403. The `kona_league_communication` view returns 401 without cookies even in a public league. (AUTH.*)
3. Parker's league is public (`isPublic = true`), so the private-league cookie path (401, 403, login page) could not be exercised live. The cookies work.
4. `statSplitTypeId` 2 exists and its meaning is unknown. For projections, split 0 is the rest-of-season total. On `leaguedefaults`, `scoringPeriodId` filters nothing: every response carries weeks 1–18. `appliedTotal` there uses ESPN's default PPR (INT −2).
5. An empty ESPN projection entry means "not projected" (backups, injured players), not a bye. ESPN projects defenses in their own bye week (31/31). Byes must come from the NFL schedule.
6. `mTransactions2` works per scoring period. `scoringPeriodId=0` and the next week both return the current week's rows. Request periods 1…current and dedupe by id.
7. Several ESPN D/ST points-allowed buckets don't line up with Sleeper keys. ESPN uses 14–17, 18–21, 22–27, 35–45 and 46+; Sleeper uses 14–20, 21–27 and 35+. That puts 14 of 24 D/ST lines in weeks 2–3 at risk. There are also 2 rules with no Sleeper key at all.
8. Values outside the §4 unions:
   - Positions: TQB, P and HC.
   - Injury statuses: DAY_TO_DAY, INJURY_RESERVE, PROBABLE and others.
   - D/ST entries have no `injuryStatus`.
   - The public test league starts a TQB and has no QB slot.
9. SWIDs appear in 13 JSON paths, 11 of them not listed in §0.5 (memberId, author, creationInfo.source and others). All are placeholdered in fixtures.
10. The public test league has drafted (§2.2 said it had not). `schedule[]` has no `playoffTierType` until the playoffs.

**Sleeper (§2.3)**
11. `/players/nfl` is 14.66 MB decoded (12,229 players), not about 5 MB.
12. Far-future projections are refreshed in season (`last_modified` 2026-09-28 for weeks 5–18), not preseason. QB/RB/WR/TE projections vary by opponent (0/335 flat), while K and IDP are flat.
13. Projection rows for bye, injured and teamless players are ADP-only stubs (no `pts_*`). `pts_*` is also left off when default-format points are 0, which covers much of IDP.
14. Projections already zero out IR/PUP players and about half of Out players in the current week. The §6 injury table would count those absences twice.
15. Projections and stats use different keys for special teams and returns (`st_td` vs `def_st_td`; `def_kr_*` vs `kr_*`). DEF points-allowed projections are one-hot bracket flags, not expected values. Of 144 keys scored across 250 leagues, 60 never appear in projections.
16. Code meanings, verified on the crawl unless marked ⚠️ (`reports/probe-output/sleeper-codes.md`):
   - `type`: 0 redraft, 1 keeper, 2 dynasty, 3 guillotine (28/250 leagues; not in §4).
   - `trade_deadline`: week D is inclusive; 99 means no deadline (⚠️).
   - `playoff_round_type`: 0 = 1-week rounds, 1 = 2-week final, 2 = 2-week rounds (⚠️, 2 leagues).
   - `league_average_match` = median game.
   - `playoff_type`: 0 toilet bowl, 1 consolation.
   - `playoff_seed_type`: 0 fixed bracket, 1 re-seed (not in §8).
   - `best_ball` = 1 (not in the spec).
   - `waiver_type` 2 = FAAB.
   - `veto_auto_poll` = 1 means a league vote; `trade_review_days` alone doesn't hold trades.
   - `position_limit_*` caps the active roster, with IR and taxi exempt.
   - `previous_league_id` can be `"0"`.
   - `settings.leg` lags the NFL week, so use `/state/nfl`.
17. Weeks at or after `playoff_week_start` return the regular-season round robin continued (week 15 = week 4 pairs), not playoff games. `/draft/{id}/traded_picks` sends `draft_id` as a bare 19-digit number that `JSON.parse` rounds. `rosters[].settings.total_moves` is always 0.
18. Past-week projections are re-stamped after the games, so the "hot" feature (§11) can't confirm they were the pre-kickoff numbers.

**Fleaflicker (§2.5)**
19. Several settings exist only on the public HTML rules page, not in the JSON API: playoff teams, weeks and byes, trade deadline, review period, tiebreakers, division-winner seeding and roster-minimum enforcement. `league.hasPlayoffs` is omitted, which reads as false.
20. Live JSON is camelCase, while the docs use snake_case. Proto3 omits false booleans and first-value enums, not just zeros.
21. There are no future-week projections, and punters are never projected. Box scores carry only display stats, so the oracle needs Sleeper stats through the Sportradar crosswalk (497/497). The DynastyProcess map finds only 7/497.
22. Stat definitions differ from Sleeper's:
   - A receiving first down includes TD catches.
   - Tackles include special-teams tackles.
   - A "≤5 returned punt yards" tier gives every QB and K +2 per game.
   Tiers also need upper bounds.
23. Other API behaviours:
   - FetchTeamPicks lists each traded pick under both teams.
   - FetchPlayerListing ignored the D/ST position filter.
   - `resultTotal` isn't a count.
   - Transactions carry no week.
   - Roster minimums are enforced, but §4 has no field for them.
   - P and K/P slots exist, but §4 Pos has no P.

**MFL (§2.6)**
24. MFL never publishes raw stats (its policy). The oracle through Sleeper stats works (604/604).
25. Lineups are a total plus per-position min–max ranges. This league can't be expressed as `SlotDef[]`, so per-position starter caps are needed. `rosterLimits` also carries minimums.
26. The trade deadline and review settings are owner-only (TYPE=calendar returns an HTTP 200 error body to guests). Owner names are hidden from guests. Errors come back as HTTP 200 plus an error object.
27. `TYPE=standings` is undocumented; use `leagueStandings`. MFL says "don't retry" and to wait one second between requests: the probe follows that instead of §0.9's backoff, with one pacing bucket for all MFL hosts. Redirects between hosts drop cookies, so they are followed manually.
28. Other quirks:
   - `endWeek` (18) isn't the fantasy final; the bracket rounds are weeks 15–17.
   - Unplayed weeks carry result "T".
   - Custom league players have IDs that collide with MFL's retired players.
   - Transactions follow a "next week to kick off" rule (verified 30/30).
   - Injuries include expected return dates.
29. MFL's league-scored projections run about 19% below Sleeper × league rules (median ratio 0.812).

**Yahoo (§2.4) and Fantrax (§2.7)**
30. Yahoo's authorize URL takes no scope parameter. `fspt-r` is an app permission set when the app is created. Two env variables were added for the OAuth probe: `YAHOO_AUTH_CODE` and `YAHOO_REFRESH_TOKEN`.
31. Fantrax responses are text/plain JSON. Errors are HTTP 200 plus an error object that echoes the league ID. The crosswalk works through Sportradar IDs (435/435), because neither FantasyCalc nor DynastyProcess has Fantrax IDs. There is no public transactions endpoint (docs only). Whether scoring rules are exposed is still unknown, since there's no public league to check.

**Shared sources (§2.9)**
32. FantasyCalc terms and docs (quoted verbatim in `reports/probe-output/shared.md`):
   - Attribution must sit close to the displayed values, not only in a footer.
   - Email FantasyCalc before a public launch.
   - Only `/values/current` and `/players` may be called; others risk an IP ban.
   - `numTeams` outside 8/10/12/14 silently returns the 12-team values.
   - `tep` must be percent-encoded (`te%2B`).
   - The redraft list holds about 198 players, and `valueFloor` (106) is above 30 real redraft values.
   - Dynasty picks look like `"2027 1st (Early)"`, with `FP_…` keys in the ID fields.
33. DynastyProcess coverage gaps:
   - `yahoo_id` is missing for nearly all 2025–26 draftees (178/250 of the top 250).
   - `fleaflicker_id` covers only 6/735 current players.
   - Team codes differ across sources (LAR/LA, WSH/WAS, JAC/JAX, …); the pairings were derived from the data.
